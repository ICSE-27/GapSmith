# GapSmith

GapSmith is a coverage-driven compiler testing framework that combines large language models (LLMs) with execution and coverage feedback. It iteratively generates high-quality test programs to improve compiler code coverage, with a particular focus on hard-to-reach regions.

## How It Works

GapSmith follows an iterative, feedback-driven workflow:

1. Collect line-level coverage data from the compiler source tree.
2. Identify uncovered regions and extract their surrounding code context.
3. Rank candidate files according to their potential coverage impact.
4. Retrieve representative unsuccessful test cases for reflective learning.
5. Summarize target regions as structured test-generation requirements.
6. Generate new test programs with an LLM, execute them, and feed the resulting coverage information into the next iteration.

## Repository Structure

### `algorithm/`

The `algorithm/` directory contains the core modules that implement the GapSmith pipeline.

| File | Description |
| --- | --- |
| `collect.py` | Collects line-level coverage data, such as `gcov` output, from specified compiler source directories. |
| `uncovered_analyzer.py` | Identifies uncovered code regions and extracts structural context, including nearby covered lines, to guide targeted test generation. |
| `sort.py` | Ranks candidate files using a coverage-driven scoring strategy to prioritize high-impact targets. |
| `find_bad.py` | Retrieves representative ineffective or misaligned test programs for a target file, enabling reflection-based prompt refinement. |
| `summarize.py` | Converts uncovered regions into structured requirements, including functional roles, triggering conditions, and relevant compiler options. |
| `generate.py` | Uses an LLM to generate test programs from the structured requirements and historical feedback. |

### `results/`

The `results/` directory contains evaluation outputs from the experimental study.

| File | Description |
| --- | --- |
| `cold_start_results.json` | Performance under cold-start conditions, without prior coverage feedback. |
| `coverage_improvement_results.json` | Coverage improvements beyond the compiler's original test suite. |
| `whitefox_comparison_results.json` | Overall comparison between GapSmith and WhiteFox. |
| `whitefox_case_results.json` | Fine-grained, case-by-case comparison with WhiteFox. |
| `ablation_study_results.json` | Ablation results measuring the contribution of individual GapSmith components. |
| `cost_analysis_results.json` | Token usage and computational cost of the LLM-based components. |
| `base_model_comparison_results.json` | Performance comparison across different base LLMs. |
| `failure_results.json` | Statistics and categories for failures encountered during test generation. |

### Main Entry Point

`main.py` orchestrates the complete GapSmith pipeline, from coverage collection and target analysis to test generation.

## Installation

GapSmith requires Python 3.8+ and depends only on the `openai` package (used to access the DeepSeek API via its OpenAI-compatible client). Install the dependencies with:

```bash
pip install -r requirements.txt
```

We recommend using a virtual environment:

```bash
pip install -r requirements.txt
```

## Usage

Before running GapSmith, configure all compiler source, installation, coverage-data, and output paths for your local environment. Then provide your DeepSeek API key and run:

```bash
DEEPSEEK_API_KEY="your_api_key" python main.py
```

Alternatively, export the key first:

```bash
export DEEPSEEK_API_KEY="your_api_key"
python main.py
```

> **Note:** Ensure that the compiler has been built with coverage instrumentation and that all required coverage tools are installed before collecting coverage data.

## Coverage Collection

### Original Compiler Test Suites

For GCC, the original test suites can be executed with DejaGnu:

```bash
runtest --tool gcc --tool_exec "${INSTALL_DIR}/bin/gcc" --srcdir "${SRCDIR}/testsuite"
runtest --tool g++ --tool_exec "${INSTALL_DIR}/bin/g++" --srcdir "${SRCDIR}/testsuite"
```

For LLVM:

```bash
ninja check-all
```

### Generated Test Programs

Compile the generated programs with the relevant compiler options for each target. After execution, collect the updated coverage data and use it as feedback for the next GapSmith iteration.

## Data Directories

| Directory | Contents |
| --- | --- |
| `programs/` | Generated test programs and intermediate artifacts. |
| `prompts/` | Prompts constructed for LLM-based test generation. |
| `summaries/` | Structured summaries of uncovered compiler regions. |
| `bad_cases/` | Representative ineffective test cases used for reflection and prompt refinement. |
| `all_programs/` | The programs generated by GapSmith, you can run them by the script in each folder and see the coverage change. |
